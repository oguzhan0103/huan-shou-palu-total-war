# 《幻兽帕鲁全面战争》v1.0.6 多人联机测试任务书

这是一份给普通玩家和社区测试者的公开任务书。不会写代码也可以参加。你要做的不是证明“Mod 已经完美”，而是让两台真实电脑、两个真实账号实际连接，按固定步骤操作，然后把成功和失败都如实记录下来。

当前版本是 **source-only 联机技术预览版**。源码和自动测试已通过，单台电脑上的监听主机会话也已经验证；真实第二客户端、远端奖励、多人袭击归属和无头独服仍需要社区实机证据。在这些任务完成前，我们不会写“多人联机全部通过”。

## 一、你最少需要什么

普通联机测试至少需要：

1. 两个不同的 Steam 账号，各自拥有《幻兽帕鲁》；
2. 两台 Windows 电脑，或你和一名朋友各用一台；
3. 两边都安装相同版本的 Palworld、UE4SS 和本测试版；
4. 一个不重要的临时世界，或重要存档的副本；
5. 能截图，最好还能录 5 至 10 分钟视频。

不要用同一个 Steam 账号同时启动两份游戏。不要直接拿唯一的重要世界做首次测试。

本预览版锁定 Steam Build `24575825`。如果 Steam 已把游戏更新到其他 Build，仍可尝试，但回报里必须写明实际 Build；“不同 Build 能启动”不能代替兼容性验收。

## 二、下载与安装（两台电脑都要做）

1. 打开本项目 GitHub 的 `v1.0.6-mp-test.1` 预发布页。
2. 下载 `PalFactionTerritory0-v1.0.6-build24575825-runtime-source.zip` 和同名 `.sha256.json`。
3. 完全退出 Palworld。
4. 备份测试世界。Palworld 存档通常位于：

   ```text
   %LOCALAPPDATA%\Pal\Saved\SaveGames\
   ```

5. 确认已经安装与当前 Palworld 匹配的 UE4SS。本项目不重新分发 UE4SS。
6. 解压测试包，把压缩包根目录里的内容复制到：

   ```text
   Palworld\Pal\Binaries\Win64\ue4ss\
   ```

7. 检查两边都存在：

   ```text
   ue4ss\Mods\PalFactionTerritory0\enabled.txt
   ue4ss\Mods\PalFactionTerritory0\Scripts\main.lua
   ue4ss\Mods\PalFactionTerritory0\Scripts\pwft\multiplayer_profile_authority.lua
   ue4ss\Mods\PalFactionTerritory0\Scripts\pwft\multiplayer_native_binding.lua
   ue4ss\Mods\PalFactionTerritory0\Scripts\pwft\multiplayer_player_services.lua
   ue4ss\Mods\PalFactionTerritory0\Scripts\pwft\multiplayer_read_model.lua
   ```

8. 两边暂时只启用本项目 Mod。其他 Mod 不是绝对禁止，但第一次测试混装会让问题来源无法判断。
9. 不要安装 `PalFactionTerritoryQAHarness0`，也不要擅自打开源码里的 QA 热键。
10. 不要把主机的 `State` 文件夹复制给客户端。每名玩家必须让服务器按自己的 UID 建立档案。

公开包不包含 Pocketpair 原版资产，也不包含本地验收使用的 Cooked PAK。缺少内容作者自建 PAK 时，一些地图覆盖层、Cooked 面板或自定义商品不会完整显示，但不影响本轮最基础的“登录、身份、断线、重连”测试。

## 三、测试前先分工

- A 玩家：开房，称为“主机”。
- B 玩家：加入 A 的房间，称为“客户端”。
- 两人同时记录北京时间；出问题时要能说出大约几点几分。
- 每一个用例结束后，两边都截图。全部结束并退出游戏后，两边都运行证据收集工具。

## 四、普通玩家必须完成的 5 个用例

### M01：两人首次连接

1. A 启动游戏，创建或打开一个允许多人加入的临时世界。
2. A 完整进入世界后，邀请 B。
3. B 加入，等待角色能正常移动。
4. 两人面对面站立，各截图一张；截图中尽量显示双方角色和当前时间。
5. 一起正常游玩 5 分钟，传送一次、打开背包一次、各按一次 `F5`。

通过标准：

- 两人都能进入同一个世界；
- 主机没有在 B 加入时崩溃；
- B 能移动、传送并正常打开本体界面；
- 主机日志中出现至少两名玩家的会话，其中远端玩家角色为 `server-remote`；
- 两名玩家不能被当成同一个可写档案。

失败标准：

- B 加入时主机或客户端崩溃；
- B 一直卡加载、进入后立刻掉线；
- 主机只记录自己，没有远端会话；
- 远端事件明显写入主机玩家档案。

`F5` 的远端面板目前属于观察项：能打开请截图，打不开也要记录，但它不会单独让 M01 判失败。原生只读快照传输还没有被宣布实机通过。

### M02：确认主机和客户端不是同一个人

1. A、B 都站在安全位置。
2. A 打开 `F5`，截图当前势力状态。
3. B 打开 `F5`，截图当前势力状态或打不开时的画面。
4. B 丢弃或捡起一个普通物品，A 不操作；然后 A 单独捡起另一个普通物品。
5. 再正常游玩 5 分钟。

通过标准：

- 主机日志中 A 和 B 使用两个不同的运行时身份；
- B 的加入、退出或普通动作不会把 A 的身份切换成 B；
- 没有出现“B 操作后 A 的 Mod 好感／身份无缘无故变化”的现象。

普通捡物品不是 Mod 奖励测试，它只是帮助视频和日志对齐时间。请不要写成“A9 奖励已通过”。

### M03：客户端退出并重连

1. B 从菜单正常退出到标题界面，A 留在世界内等待 60 秒。
2. B 使用同一个 Steam 账号、同一个角色重新加入。
3. B 进入后再活动 3 分钟，打开背包和 `F5`。
4. A、B 各截图一张。

通过标准：

- B 能重新加入；
- 主机没有崩溃；
- B 重连后继续对应原来的玩家身份，而不是占用 A 的身份或生成无限重复会话；
- A 在 B 离线的 60 秒内仍能正常活动。

如果第一次重连失败，再试一次并记录两次的准确现象；不要反复重试到“偶然成功”后只上报成功。

### M04：主机退回标题并重新开房

1. B 正常退出。
2. A 退回标题界面，等待 30 秒，不要强制结束进程。
3. A 再次打开同一个测试世界并邀请 B。
4. B 再次加入，双方活动 3 分钟。

通过标准：

- 返回标题和第二次开房均不崩溃；
- 第二次世界会话能重新建立；
- 旧世界的临时控制器不会继续接受新世界事件；
- 同一玩家仍对应自己的档案。

### M05：30 分钟稳定性

1. A、B 连续在线至少 30 分钟。
2. 期间至少进行：一次传送、一次死亡后复活或倒地救援、一次 B 退出重连。
3. 有条件可去小型聚落、商人商会等机制较多的区域，但不要启用 QA 热键。
4. 记录卡顿、崩溃、断线、界面异常发生的时间。

通过标准：

- 两边均无 `Fatal error` 或 `EXCEPTION_ACCESS_VIOLATION`；
- 主机没有因为登录／登出积累出明显重复事件；
- B 重连后仍可正常活动。

## 五、进阶机制测试（只有拿到专用 QA 包才做）

以下内容是本次联机最终必须补齐的证据，但正式源码默认关闭测试热键。普通玩家不要自己改 `config.lua`。维护者发布带精确步骤、自动备份和恢复工具的专用 QA 包后，再认领这些任务：

| 编号 | 要验证什么 | 真正通过的标准 |
| --- | --- | --- |
| M06 | 两名玩家分别造成势力成员／平民后果 | 只改变实际出手玩家的侧车；未知来源不扣主机；两份状态互不串档 |
| M07 | 远端玩家获得 A9 高难奖励 | 物品进入 B 的背包，不进入 A；B 的独立账本为 applied；重复同一 operation 不再发第二份 |
| M08 | 两人同时参与帕鲁袭击 | 击杀头领的精确玩家或其所属帕鲁获得结算；未知归属不回退主机；同一事件只结算一次 |
| M10 | 远端只读势力 UI | 快照 UID、档案键、世界代际和序号匹配 B；旧快照、A 的快照和可写数据均被 B 拒绝 |

进阶测试必须同时提交主机和客户端证据。只看物品动画、只看一张截图或只看到 HTTP／Hook 成功，都不能单独写“通过”。

## 六、独立服务器测试（有经验者认领）

编号 M09，至少准备一台 Windows PalServer 和两名真实客户端：

1. 服务器与两名客户端使用相同 Build 和相同 Mod 提交；
2. 先启动无本地玩家的服务器，保留启动日志 2 分钟；
3. A 加入，等待 2 分钟；B 再加入；
4. A 退出，B 留在服务器活动 5 分钟；
5. A 重连；随后 B 退出；
6. 正常关闭并重启服务器，两人再次加入；
7. 核对每名玩家仍是独立档案，服务器无本地玩家时也没有把事件错误写给“主机”。

必须记录服务器启动参数中与 Mod 加载有关的部分，但公开回报前删除密码、公网 IP、Steam ID 和任何认证令牌。

## 七、怎么收集证据

全部测试结束后，先正常退出游戏，然后两台电脑分别双击发布包里的：

```text
CommunityTestTools\收集联机测试证据.cmd
```

选择本机角色：主机选 1，客户端选 2，独服选 3。工具会在桌面生成：

```text
幻兽帕鲁全面战争_联机测试证据\PWFT-Multiplayer-角色-时间.zip
```

这个 ZIP 只包含：

- 本 Mod 和联机相关的脱敏日志行；
- Build、脚本哈希和自动摘要；
- 一份待填写的中文回报模板。

工具不会打包 Palworld SaveGames、`State` 原文件、完整 UE4SS.log、Steam 登录令牌或密码。先打开 ZIP 里的 `请填写_测试回报.md` 补全内容，再连同两边截图／视频链接提交。

## 八、到哪里回报

在 GitHub 任务 `【招募测试】v1.0.6 多人联机真实双机与独服验证` 下回复。每一组测试至少提交：

1. A、B 两台电脑各自的证据 ZIP；
2. 两边同一时刻的截图；
3. 使用的预发布标签或完整提交号；
4. M01 至 M05 每项的“通过／失败／没做”；
5. 第一次异常的北京时间和复现步骤；
6. 是否混装其他 Mod。

成功结果和失败结果同样有价值。请不要只写“能用”“闪退”“卡了”，也不要把别人的截图当作自己的结果。

## 九、常见问题

### 1. 一连接就提示 EOS 错误

两边先完全退出 Palworld 和 Steam，再重启 Steam 登录后重试一次。如果仍出现 `EOS_Connect_ExternalTokenValidationFailed`，停止重复尝试，提交两边证据。这是有效的阻塞结果，不算你测试失败。

### 2. UE4SS 崩溃是不是因为 Lua 多

不能只按 Lua 文件数量判断。请提交崩溃时间、两边版本、脱敏日志和复现步骤；只有相同提交、相同 Build 下能稳定复现，才能定位是脚本、UE4SS、游戏 Build 还是其他 Mod 冲突。

### 3. F5 在客户端没有正确显示

照实截图并记录。当前只读数据模型已经完成，原生网络传输和远端面板仍是待验证／待接线项；它不是“已承诺一定通过”的功能。

### 4. 可以上传整个存档让开发者看吗

不要发到公开 Issue。先发脱敏证据包；只有维护者明确要求并给出私密渠道时，才考虑提供测试世界副本。

### 5. 测试后不想保留 Mod

使用发布包中的 `快速卸载_幻兽帕鲁全面战争.cmd`。工具会先预览精确目标，并在删除本 Mod 前备份 Mod 自有 `State`；它不会删除 Palworld 世界存档、UE4SS 或其他 Mod。

## 十、完成定义

一个用例只有在“操作步骤、双方日志、双方画面和状态结果”一致时才记为通过。源码测试通过、脚本加载、Hook 注册、单机画面或一方日志，都不能代替真实双客户端／独服验收。
