# 势力进度与内容接口底座

更新日期：2026-07-28  
适配版本：Palworld 1.0.1 / Steam Build 24181527  
当前状态：**机制核心已实现并通过离线测试；尚未进行本轮实机验收**

## 1. 本阶段边界

这一阶段只建设可承载粉丝任务、商业和防守内容的机制底座，不制作具体剧情、任务对白或势力故事。

- 玩家可以同时加入多个**人类势力**。
- 玩家不能加入帕鲁势力。
- 初始状态下，所有人类势力为蓝色友好、未加入；所有帕鲁势力为红色敌对。
- 人类势力关系为负数时显示红色；非负且未加入时显示蓝色；加入后显示绿色。
- 当前阶段只处理好感度增长，不处理好感度下降、降级或权限回收。
- 商业是有限的关系修复来源；任务与保卫战是主要好感度来源。
- 所有人类势力达到领主后，才解锁帕鲁势力和解阶段。
- 所有人类势力达到领主、所有帕鲁势力转为蓝色后，结局三条件成立。

## 2. 版本化合同

机制合同：

```text
contracts/faction_progression.v1.json
```

合同当前定义：

- 7 个人类势力、5 个帕鲁势力。
- 多人类势力成员身份。
- `成员 / 核心成员 / 领队 / 领主` 四级身份。
- 领队开始解锁玩家护卫资格。
- 任务、防守、商业三种好感度来源。
- 商业负关系修复额度和非负关系增长额度。
- 帕鲁和解与结局三的前置条件。
- 禁止修改 Palworld 原生存档。

身份阈值和商业额度当前属于**待实机平衡的暂定值**，不是最终数值承诺。

## 3. 运行时核心

核心实现：

```text
mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_progression.lua
```

它负责：

- 创建并校验 12 个势力的初始状态。
- 独立保存每个人类势力的好感度、成员身份和等级。
- 从进度状态派生地图、地名、传送与商人共用的关系颜色。
- 限制商业好感度额度。
- 阻止帕鲁势力被加入。
- 计算护卫资格、帕鲁和解解锁和结局三解锁。
- 导出、恢复版本化状态快照。
- 使用事件 ID 防止同一任务、交易或防守结算被重复计分。

## 4. 粉丝内容接口

稳定接口：

```text
mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_api.lua
```

运行时入口：

```lua
local api = _G.PWFT_FACTION_API_V1
```

内容包只需要在自己的任务或事件完成点调用对应接口：

```lua
api:join_human(
    "pwft.faction.rayne_syndicate",
    "community.rayne.recruitment"
)

api:award_task(
    "pwft.faction.rayne_syndicate",
    150,
    "community.rayne.task.001"
)

api:award_defense(
    "pwft.faction.rayne_syndicate",
    250,
    "community.rayne.defense.001"
)

api:award_commerce(
    "pwft.faction.rayne_syndicate",
    10,
    "community.rayne.trade.0001",
    "world-day-0042"
)
```

每个完成 ID、交易 ID 和防守结算 ID 必须唯一。重复调用同一个 ID 时，接口返回 `duplicate-event`，不会重复增加好感度。

帕鲁和解接口已经预留，但必须先满足所有人类势力领主条件：

```lua
api:reconcile_pal(
    "pwft.faction.dark_nocturnal_pal_tribe",
    "community.pal.dark.reconciliation.001"
)
```

具体如何在玩法中达成帕鲁和解，等待后续设计；底层门槛和结局条件不需要重写。
