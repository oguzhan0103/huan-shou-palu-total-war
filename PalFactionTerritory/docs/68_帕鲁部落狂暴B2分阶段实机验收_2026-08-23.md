## 1. 结论

B2 的原生字段与作用域门通过，正式配置仍默认关闭。

- 实机在 `pwft.island.central_southeast_archipelago` 捕获 11 个自然生成目标实例，覆盖 PinkCat、ChickenPal、SheepBall。
- 每个目标均从 Predator=false、HP/伤害倍率=1、生成类型=0、可捕获，变为 Predator=true、HP/伤害倍率=2、生成类型=8、不可捕获；最大 HP 原始值逐个精确翻倍。
- 玩家、5 个拥有／工作帕鲁及后续 group 4 非世界目标均在任何写入前排除，日志中的原生字段保持原值。
- 临时强制 mask miss 的独立负对照中，8 个自然野生帕鲁均按岛外排除，稳定审计为 `applied=0 verified=0 excluded=14 failed=0`。
- 两轮都只消费当前原生初始化事件，不运行 `FindAllOf` 或加载对象协调；B1 等级门全程关闭。
- 测试后 SaveGames 385/385、Mod State 12/12 按测试前快照恢复，哈希差异为 0；76 个正式运行文件重新部署，源码与安装一致。

这里的 `PASS` 只覆盖原生字段和作用域门。没有把未直接观察的战斗演出、实际投球失败或用户主观验收写成通过。

## 2. 为什么需要修改旧资格判断

Build 24575825 的普通野生帕鲁在原生初始化后仍然是 `GroupType=0 / Undefined`。旧实现把 0 当作未知状态并失败关闭，结果是真正的野生目标也永远不会进入 B2。

本轮把资格收敛为：

1. group 0 只有在 `OwnerPlayerUId` 四段均可读且全为 0 时才视为无主野生帕鲁；
2. owner GUID 非零立即按 `save-owner-assigned` 排除；
3. owner 状态不可读仍失败关闭；
4. Neutral、ResidentEnemy、RaidBoss 的已知世界敌人组继续允许；
5. Otomo、工作帕鲁、训练师归属、玩家公会和其他非世界组继续排除。

这修复了真实目标漏判，同时没有放宽玩家与剧情对象保护线。

## 3. 正向目标实机结果

首批四个实例的摘要为：

```text
RAGE_AUDIT_SUMMARY ... applied=4 verified=4 excluded=6 failed=0 ... broadScan=false levelEnabled=false loadedActorReconcile=false
```

四个实例分别为两只 PinkCat、一只 ChickenPal、一只 SheepBall。典型精确读回：

```text
PAL_FACTION_RAGE_VERIFIED ... group=0 ownerAssigned=false level=80
beforePredator=false beforeHpRate=1.0 beforeDamageRate=1.0 beforeSpawnedType=0 beforeUncapturable=false
afterPredator=true afterHpRate=2.0 afterDamageRate=2.0 afterSpawnedType=8 afterUncapturable=true
beforeMaxHpRaw=601000 afterMaxHpRaw=1202000 ... broadScan=false
```

随后自然流入的 7 个实例也逐个出现同样的精确读回，因此本轮共有 11 个目标实例通过，而不是只依赖首个四目标摘要。

## 4. 排除与负对照

### 4.1 玩家和自有帕鲁

| 对象 | 原因 | 结果 |
| --- | --- | --- |
| 本地玩家 | `not-pal` | Predator=false、倍率 1、类型 0、可捕获字段未改 |
| 5 个基地／拥有帕鲁 | `owned-or-worker`，group 4，ownerAssigned=true | 全部字段未改 |
| 后续 group 4 对象 | `non-world-group:4` | 全部字段未改 |

### 4.2 强制岛外负对照

为了让同一批自然生成对象在相同存档、位置和加载条件下走一次“岛外”分支，只在已安装测试运行时临时让 mask classifier 返回 nil；仓库源码没有修改。该方法是受控 mask miss，不是玩家自然走到另一个地理区域。

稳定摘要：

```text
RAGE_AUDIT_SUMMARY ... applied=0 verified=0 excluded=14 failed=0 outcomes=excluded:not-pal:2,excluded:outside-pal-faction-island:7,excluded:owned-or-worker:5 ... broadScan=false
```

摘要之后又流入一只 MysteryMask，同样按岛外排除，所以完整日志共有 8 个自然野生岛外排除实例。它们全部读回 Predator=false、倍率 1、类型 0、可捕获。

## 5. QA 探针与现场问题

- F7 PinkCat 探针在日志中显示 `PAL_FACTION_RAGE_PROBE_READY`，但另一已安装 Mod `PalMultiOtomo0` 也把 F7 注册为召回键，本轮没有生成 `PROBE_OBSERVED` 样本。探针不计为 B2 通过证据；自然生成实例已经提供正向和负向证据。
- 正向轮出现一次 `COMPANION_COMMERCE_EVENT_DEFERRED ... json.lua:16`，标题页随后显示本体的 Mod 异常提示。这是独立的 companion commerce 事件编码问题；B2 日志仍为 11 个 VERIFIED、0 个 FAILED。该问题已在后续修复并实机复核，见 `docs/69_商会Companion_JSON边界修复与实机复核_2026-08-23.md`。
- 没有直接拍摄 Predator 的战斗行为，也没有实际投球验证捕获失败。本轮只把精确原生属性读回记为通过。
