# 小型聚落兽潮原生生命周期修复

日期：2026-07-30  
状态：**源码、原生合同、全量离线回归与部署均通过；未启动游戏，待用户下令实机验收**

## 1. 昨日故障

2026-07-29 实机测试已经证明：

- 倒计时和预警 UI 可以正常工作；
- 三种调试入口没有创建真实 Incident；
- 直接调用内部 `RequestIncident...` 的第四种路线在倒计时结束后造成
  `EXCEPTION_ACCESS_VIOLATION`，读取地址 `0x5d`；
- 崩溃后已撤下危险实现并关闭 QA 热键。

这说明问题不在预警 UI，而在原生入侵管理器的生命周期被绕过：内部请求依赖
世界已有的 Observer、动态参数和 Incident 状态，不能由 MOD 手工拼装。

## 2. 当前修复

当前实现只使用游戏公开、世界持有的管理器生命周期：

1. 通过 `PalUtility.GetInvaderManager(WorldContextObject)` 取得当前世界已经初始化的
   `PalInvaderManager`。
2. 用目标基地 `FGuid` 调用
   `PalInvaderManager.StartInvaderMarchForBaseCamp(campId)`。
3. 在原生 `PalInvaderIncidentBase.SelectInvaders` 阶段把选择参数限定为：
   `Grade=80`、`Biome=Meadow(1)`。
4. 原生数据表据此选择
   `Invader_Group_Monster_Grade5_Basic`；该组的正式等级带为 `61–80`。
5. 保留小型聚落的入侵起点、目标点、生成后 80 级和目标阵营重定向钩子。
6. 五个必要原生钩子采用启动立即注册、`250/1000/3000/8000 ms` 有限重试，
   并在倒计时结束前做最后一次同步注册。钩子未全部注册时拒绝启动。
7. 五秒确认窗口内没有同时观察到
   Incident、管理器 `InvaderInfo` 和选择重定向时，当前模块失败关闭。

昨日日志已经证明三个蓝图函数并未从 Build 24370881 删除：首次注册发生在资产
尚未加载时会失败，`LoadAsset`/世界加载后相同路径能够成功注册。因此当前修复
针对的是确定的加载时序，不再把早期注册失败误判成版本删函数。

## 3. 已彻底移除的危险路线

- `RequestIncidentInvaderEnemy_BP`

- `InvaderMarchForNearestCamp`

控制台显式执行 `pwft.raid start 5`。
