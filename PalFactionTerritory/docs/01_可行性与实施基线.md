# 可行性与实施基线

## 结论

**有条件可行。** 本体已经提供完成 MVP 所需的大部分内容：瞭望塔解锁状态、地图区域遮罩、世界地图 UI、可着色遮罩材质、快速传送判定入口和关系／人物原文。最稳定的路线是复用本体资产并增加薄运行时适配层，而不是替换地图或复制整张 UI。

当前可完成离线规则与数据切片，但不能声称游戏内实现完成。阻塞原因是缺少当前 1.0.1 build 的运行时框架、Mod SDK 和属性映射。

## 功能可行性矩阵

| MVP 功能 | 本体证据 | 当前状态 | 游戏内接入条件 |
|---|---|---|---|
| 瞭望塔区域绑定 | 24 个 `WatchTower_*` 文本 ID；`BP_LevelObject_UnlockMapPoint`；20 张区域遮罩 | 24 个稳定 ID 已建契约；1 号塔所有者有原文证据 | 生成当前 `.usmap`/SDK，精确导出塔、遮罩、位置绑定 |
| 保留原始地图 | `WBP_Map_Base` / `WBP_Map_Body` 与原地图纹理 | 架构确定为默认不改本体 | 只注入附加 Overlay 和开关，关闭时不执行绘制 |
| 势力版图图层 | `M_WorldMapMaskPaint_FixedTexture` 暴露 `MaskTexture`、`SelectionColor` | 着色策略已确定 | 在原地图上增加临时 Image 层，直接引用本体遮罩和材质 |
| 红／绿／蓝动态关系色 | 本体材质支持动态颜色参数 | 离线核心已实现并测试 | 接入一个最小关系存储与变更事件；客户端刷新 Overlay |
| 未解锁区域保留迷雾 | `WBP_Map_Body` 的默认遮罩与 `Image_MapMask` | 离线策略明确不绘制未解锁区 | 读取本体解锁状态，不修改本体 Fog/Mask Render Target |
| 势力名、控制者／塔主、关系 | 本体势力名、塔主名、地图信息 UI | 稳定数据字段已定义 | 使用本体文本键；在原地图信息窗中追加最小三行信息 |
| 敌对公共传送限制 | `WBP_Map_Body::CanFastTravel`；塔传送对象 `CheckUnuseFastTravel` | 离线规则已实现并测试 | 同时拦截地图点击和场景内交互，服务端再次校验 |
| 入境提示 | `WBP_Crime_Found` / `WBP_Crime_Scene` | 明确推迟 | 只有证实可隔离展示、不产生犯罪状态时才接入 |

## MVP 边界

包含：

- 24 座本体瞭望塔的稳定区域 ID。
- 势力、控制者和关系状态的稳定契约。
- 原始地图／势力版图切换。
- 解锁区按玩家关系着色；未解锁区继续使用本体迷雾。
- 关系变化后只刷新受影响区域。
- 敌对领地的公共传送禁用，覆盖地图入口与场景入口。
- 条件合适时才增加入境提示。

不包含：

- 领土争夺、动态扩张、城市毁灭。
- 商队、经济、守城、兽潮、结局。
- 新地图、新 NPC、新服装、新材质或复制本体 UI。
- 自定义 `EPalTribeID`。该枚举是帕鲁物种枚举，不是势力 ID；第一版不会滥用或扩展它。
- 对没有证据的塔区强行分配势力。

## 稳定性基线

1. 原地图是唯一底图；势力版图只是可关闭的附加层。
2. 不替换 `WBP_Map_Body`，不覆写整张 DataTable，不打包本体资产副本。
3. 所有势力与塔区用 Mod 自有稳定字符串 ID，另存本体 ID／文本键作为绑定；不改本体枚举。
4. 数据只写必要字段；未验证的所有者、遮罩、运行时组绑定保持 `null`。
5. 传送限制必须在权威侧再次检查，客户端 UI 禁用不能作为唯一安全措施。
6. 所有持久状态带 schema 版本；卸载后不应破坏原存档或原地图。
