## 2. 为什么还不能把状态改成 `bound`

PAK 中“有这个资产”只能证明可行路线，不等于游戏内已接通。P1 Provider 在激活前还必须取得：

1. 当前世界里的确切 spawner UObject 身份与地点；
2. 该 spawner 实际生成的 Actor class 和唯一 Actor 实例；
3. 开放、关闭、冷却和返回标题后的单实例行为；
4. 等级、生命、伤害、减伤、异常抗性和捕获难度组成的完整 `raid-slab` 档；
5. 生成、击败、捕获和超时四类权威回调；
6. world generation fencing，确保旧世界回调不能结算新世界。

这些项目需要部署后的受控实机核验。本轮没有启动 Steam、Palworld、UE4SS 或 Unreal Editor，也没有修改游戏目录或存档。

## 3. 石板 Boss 强度的本地参照

参数表中已找到 17 个 `IsRaidBoss=true` 行。高难度 `_2` 行的 `EnemyReceiveDamageRate` 样本约为 `0.085`、`0.09`、`0.20`、`0.25`，说明仅把普通 Boss 的 `IsBoss` 打开并不能达到石板 Boss 强度。等级、生命倍率和实际伤害仍可能由生成器或战斗实例共同决定，因此本轮没有凭单个字段猜出正式数值。

后续平衡 Provider 必须一次性提交完整 `raid-slab` 档，不能只改减伤，也不能把 `captureAllowed` 关掉。

## 4. P2 可复用与仍缺的接口

已经可直接复用的项目：

- 商人商会已有七个稳定势力账号、商人 ID、Actor 记录和按势力停用入口；毁灭后过滤对应柜台不需要再次设计七套商人。
- `UniquePalWorldEffectBus` 已具备精确刷新抑制、绑定 Actor 清理、保留建筑的空城、商会过滤、后台战争、玩家保卫、赎金与 Pal 交付的幂等账本和回调门禁。
- 旧 ObjectDump 可证明 `PalPlayerState:GetInventoryData`、`PalItemContainer:GetItemStackCount`、`PalPlayerState:GetPalStorage`、角色容器管理器和捕获回调等候选接口存在。

仍不能直接接通的项目：

- 当前 Build 的金币扣款必须走服务器权威路线，不能只改客户端 `Money` 数量；
- Pal 实际交付的通用事务桥已补齐目标容量预检、固定 individual identity、服务端创建/捕获、仓库回读、幂等重试和未提交创建回滚；Build 24575825 的当前签名及单只 Anubis 原生交付路线已实机通过，但生产 P2 target binding 仍为 0；
- 势力刷新器、城市锚点、居民/功能 NPC 刷新器以及允许清理的已加载 Actor 尚未逐城绑定；
- 樱岛条目仍是“战略地点毁灭”，不得偷换为“月花众毁灭”；
- 玩家保卫成功后的唯一帕鲁归属/停战语义尚未由负责人确定，Provider 继续失败关闭。

因此 P2 的通用源码已经完成，支付与交付也各有失败关闭事务桥，当前 Build 交付适配器已有单路线实机证据；“城市真实 Provider、正式赎金商品、P2 生产 target binding 和支付→交付组合验收”仍是当前缺口。

## 5. 空涡龙边界

“空涡龙—天坠之地”仍是暂定条目。本地没有足够权威证据确认其内部 species ID，本轮目录将 `speciesId` 保持为 `null`，不创建稳定唯一帕鲁 ID，不绑定 Actor、spawner 或毁灭事件。

## 6. 复验命令

离线检查合同与证据边界：

```powershell
python .\tools\verify_unique_pal_native_assets.py
```

只读核对当前已安装 PAK 的 17 个关键条目（参数表 4 个、候选生成器 8 个、Boss Actor 5 个）：

```powershell
$PalPak = "<Palworld安装目录>\Pal\Content\Paks\Pal-Windows.pak"
$Repak = "<repak目录>\repak.exe"
python .\tools\verify_unique_pal_native_assets.py `
  --pak $PalPak `
  --repak $Repak
```

该命令只执行 `repak get` 到内存并计算 SHA-256，不解包整包、不写游戏目录，也不启动游戏。
