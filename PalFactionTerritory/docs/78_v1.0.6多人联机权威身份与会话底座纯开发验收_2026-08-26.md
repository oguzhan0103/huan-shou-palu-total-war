# v1.0.6 多人联机权威身份与会话底座开发与主机实机验收

日期：2026-08-26
分支：`codex/v1.0.6-technical-multiplayer`

## 结论

本轮完成了多人联机的服务器权威身份、逐玩家 Mod 侧车上下文、登录／登出、重连、换图清理和精确事件归属底座。末次公共验证通过：113 个 Lua 文件、89 个 Lua 测试、489 个跟踪文本文件；当前开发版也已完成单进程监听主机实机烟测。

该结论是“开发验证与单进程监听主机实机通过”，不是“真实双客户端或独立服务器实机通过”。真正的远端客户端和无头独服仍须分别启动真实进程验收。

## 本轮完成

1. 新增 `multiplayer_profile_authority.lua`：
   - 只接受服务器权威控制器；
   - 以精确 `WorldDirectory + PlayerUId` 建立一人一档；
   - 主机复用当前本地势力上下文，远端玩家建立独立上下文；
   - 同一玩家重连时替换旧控制器会话但复用玩家档案；
   - 登出和换图先保存侧车，再清除所有 UObject／控制器引用；
   - 世界代际不一致、伪造客户端权威、身份不完整均失败关闭。

2. 新增 `multiplayer_native_binding.lua`：
   - 当前 Build 路线：`GameModeBase.K2_PostLogin`、`GameModeBase.K2_OnLogout`；
   - 启动或换图后枚举现有 `PalPlayerController`，覆盖脚本晚加载场景；
   - 本地监听主机、服务器远端控制器和无本地控制器的独服使用同一生命周期；
   - 非权威客户端只记录 observer 状态，不创建可写上下文；
   - 不信任自定义客户端 RPC，也不把模型当作状态权威。

3. 修复多人事件串档风险：
   - 旧绑定能识别远端 `PalPlayerController`，但结算仍落入唯一的本地主机后果路由；
   - 现在服务器伤害回调先把控制器解析到精确玩家会话，再选择该玩家的 `FactionConsequenceRouter`；
   - 远端玩家伤害只扣远端玩家档案，不再扣主机档案；
   - 找不到控制器会话时直接返回 `native-consequence-player-context-unavailable`，绝不回退到主机。

4. 新增版本化契约 `contracts/multiplayer_authority.v1.json`，并纳入注册表生成与公共验证器。

5. 补齐逐玩家玩法服务：
   - `multiplayer_player_services.lua` 为主机和每名远端玩家维护独立 A9 奖励账本与帕鲁和解服务；
   - 内容包通过 `PWFT_MULTIPLAYER_PLAYER_SERVICES_V1` 一次注册奖励频道／帕鲁配置，当前玩家与后加入玩家获得一致定义；
   - A9 原生适配器从服务器已登记会话解析精确控制器，再按 `OwnerPlayerUId` 选择唯一背包；远端控制器走服务器内部发放，不再强制匹配本地主机；
   - 帕鲁袭击从直接玩家或其帕鲁训练师控制器提取精确 UID，头领击杀只结算到该玩家的和解侧车；未知、重复或无法解析的控制器继续失败关闭。
   - `multiplayer_read_model.lua` 生成逐玩家只读 UI 快照，包含精确 UID、档案键、世界代际、递增序号和势力行；客户端拒绝跨玩家、过期、档案不匹配或声明可写的快照。该协议不自称已经绑定原生网络传输。

## 已覆盖的自动场景

- 单机／监听主机身份；
- 服务器远端控制器；
- 非权威本地客户端只读观察；
- 登录、登出和启动时已有控制器扫描；
- 同 UID 重连；
- 过期世界代际拒绝；
- 登出和换图持久化；
- 无本地控制器的 dedicated-ready 生命周期；
- 远端成员／平民伤害归入远端档案；
- 未知控制器失败关闭且主机、远端档案均不变化；
- 运行时初始化、换图前清理、换图后重新枚举。
- 当前／后加入玩家的奖励频道与帕鲁内容重放；
- A9 主机与服务器远端控制器的精确背包选择；
- 本地主机、远端玩家和其持有帕鲁的头领击杀逐玩家结算。
- 远端 UI 只读快照的跨玩家、过期和可写负向拒绝。

## 安全边界

- 不写 Palworld SaveGame，只写 Mod 自有侧车。
- 不持久化 UObject。
- 客户端不能直接修改好感、身份、奖励或战争状态。
- Ollama／Agent 继续只有文本建议权。
- 自动测试和单进程主机烟测不能替代第二客户端／独服验收。
