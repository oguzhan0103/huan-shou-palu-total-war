# 唯一性帕鲁 Boss 开放与势力毁灭战争机制（2026-08-13）

## 1. 文档状态

本文记录项目负责人确定的新机制方向。它取代“唯一性帕鲁只是一枚静态毁城许可”的简化理解，但继续沿用现有 `StrategicWorld` 的单一归属、归属转移、毁灭权限和永久世界状态能力。

当前状态为**设计基线，尚未完成原生接入与实机验收**。本轮不启动游戏、不修改原始存档、不删除游戏资产，也不把暂定映射接入不可逆触发。

具体帕鲁与毁灭目标见《[唯一性帕鲁与势力毁灭映射](52_唯一性帕鲁与势力毁灭映射_2026-08-13.md)》。其中前五项已确定，“空涡龙—天坠之地”仍为暂定。

## 2. Boss 唯一性规则

1. 唯一性帕鲁清单是全面战争 Mod 的**帕鲁 Boss 白名单**。
2. 非白名单帕鲁不再保留独立 Boss 刷新或挑战入口；实现时优先禁用或重定向刷新器，不直接删除游戏资产。
3. 某只唯一性帕鲁若原生已有 Boss 版本，复用其原生 Boss Actor、技能和表现。
4. 若原生没有 Boss 版本，则选择一个兼容且不再使用的原生 Boss 槽位，把该槽位的物种替换成目标唯一性帕鲁。具体替换槽位属于配置内容，不硬编码在核心状态机中。
5. 唯一性帕鲁强度统一对准石板召唤 Boss 的强度档位，包括等级、生命、伤害、减伤、异常抗性和捕获难度；石板 Boss 在这里是数值基准，不自动等同于仍需保留的额外战略 Boss。
6. 唯一性帕鲁必须可以被捕获，因为捕获结果会决定其唯一归属。任何时候同一唯一性帕鲁只允许存在一个有效归属和一个有效世界实例。
7. 高塔训练师战、剧情专用战和非帕鲁类 Boss 是否属于移除范围尚未确定，不在本条中自行扩大删除范围。

## 3. 不定时开放机制

每只仍处于 `wild/unclaimed` 状态的唯一性帕鲁按以下状态运行：

`关闭 -> 预告 -> 开放 -> 玩家捕获或超时结算 -> 关闭`

- **关闭**：世界中不生成该 Boss，玩家不能随时挑战。
- **预告**：开放前向玩家显示文本通知，至少包含唯一性帕鲁名称、开放地点和开放倒计时。
- **开放**：在指定 Boss 槽位生成唯一实例，并开启捕获结算。
- **玩家捕获**：以服务器/原生权威捕获结果为准，将唯一归属转移给玩家，立即结束本次开放。
- **超时未捕获**：回收本轮世界实例，并从仍存续的 NPC 人类势力候选池中确定一个势力，将唯一归属转移给它。
- **防重复**：同一开放批次、捕获事件或超时事件必须使用稳定 operation ID；迟到、重复和冲突结果一律不重复生成、不重复转移。

“不定时”由可配置的最短间隔、最大间隔、预告时长和开放时长控制。随机选择必须保存抽样结果，重启游戏后不得因为重新抽样而改变既定归属。候选池是否排除该帕鲁对应的毁灭目标势力，留作内容配置项，当前不擅自决定。

## 4. 唯一归属与毁灭权限

- 唯一性帕鲁的归属只能是 `wild/unclaimed`、玩家或一个仍存续的人类势力。
- 每只唯一性帕鲁对应一个势力或战略地点的毁灭结果。
- 玩家或 NPC 势力只有持有对应唯一性帕鲁时，才拥有对该目标发动永久毁灭的权限。
- 没有对应唯一性帕鲁的攻击者不能完成永久毁灭；现有 Boss 生命 1 点门闩继续作为失败关闭的底层保护。
- “某势力的唯一性帕鲁”在机制语义上是**能够决定该势力生死的唯一毁灭密钥**，不表示该帕鲁初始就归该势力所有。

## 5. NPC 势力的后台毁灭战争

当一个 NPC 人类势力取得唯一性帕鲁后，它可以对该帕鲁对应的 NPC 势力或战略目标发起毁灭战争。

- 战争发生在玩家视野之外，不要求生成军队、播放攻城演出或模拟完整 NPC 战斗。
- 游戏只需发布预告、开战、结果等文本事件，并在后台状态机中完成幂等结算。
- 发起者必须仍存续且仍持有对应唯一性帕鲁；目标必须尚未毁灭。
- 战争触发概率、准备期、冷却期以及后台胜负规则由可配置策略决定，不能依赖大模型临场决定。
- 一旦后台结算为目标毁灭，就提交永久势力毁灭状态并执行第 7 节的世界效果。

## 6. 玩家加入势力后的保卫战

如果玩家已经加入某个目标势力，而对应的唯一性帕鲁被另一个人类势力持有，则该 NPC 势力发起毁灭战争时，不直接在后台消灭玩家所属势力，而是转为一次**针对玩家的保卫袭击**：

1. 开战前向玩家显示目标势力、进攻势力和倒计时。
2. 使用现有玩家袭击/保卫结果桥进行实际战斗。
3. 玩家方胜利：本次毁灭战争失败，玩家所属势力继续存续。
4. 玩家方失败：该势力进入永久毁灭状态。
5. 玩家可加入多个势力；每次保卫战只结算被攻击的那个势力，不连带毁灭玩家加入的其他势力。

玩家赢得保卫战后，敌方持有的唯一性帕鲁是否自动转移、继续由敌方持有或进入一段强制停战期，项目负责人尚未确定。实现前必须补齐该内容密钥，不能因为保卫成功自行把帕鲁发给玩家。

## 7. 势力毁灭后的世界效果

势力毁灭是持久、跨重启的世界状态。至少产生以下效果：

- 该势力的地图 NPC、巡逻队、据点人员和同势力战斗刷新不再出现；
- 该势力范围内的城镇建筑保留，但居民和势力功能 NPC 不再刷新，形成空城/空房子；
- 商人商会中该势力对应的商人柜台不再生成；
- 已经加载的相关临时 Actor 在安全的世界生命周期阶段回收，之后刷新器持续失败关闭；
- 后台战争、任务入口和商会逻辑不得把已毁灭势力重新选入候选池；
- 不直接删除地图、建筑或原生资产，也不直接修改受保护的 Palworld 存档；永久状态写入 Mod 自有 sidecar。

该势力已有任务如何终止、玩家身份如何显示、传送点是否保留以及残余中立商人如何处理，尚未确定，不在本基线中擅自补写。

## 8. 商人商会高额赎回

如果另一个人类势力持有了能够毁灭玩家已加入势力的唯一性帕鲁，玩家可以通过商人商会支付极高赎金把它买回来。

- 赎回入口绑定当前持有者势力的商会商人或商会公共服务，不依赖已经毁灭目标的商人。
- 只有当前权威归属确实是该 NPC 势力时才显示并允许支付。
- 支付必须走原生金币扣除与确认结果；取消、余额不足、重复回调和失败交易均不得转移归属。
- 支付确认后，唯一性帕鲁归属转移给玩家，并取消尚未结算的对应毁灭战争或保卫袭击。
- 同一只唯一性帕鲁不能因重复交易被生成两次。
- 赎金必须“非常非常高”，但具体金额尚未确定；采用每只唯一性帕鲁独立的 `ransomPrice` 配置，不在核心代码中猜写价格。
- 赎金交易是否产生商业好感度尚未确定；在明确前默认不借此绕过商业好感度额度。

## 9. 对现有代码基座的影响

现有能力可以继续复用：

- `StrategicWorld`：唯一帕鲁单一归属、乐观转移、毁城权限、Boss 1 HP 门闩、城市永久状态；
- `StrategicWorldNativeBus`：精确 Actor/Class 绑定、捕获、Boss 伤害/死亡和城市加载事件；
- 玩家袭击与保卫结果桥：玩家参与、胜负与幂等结算；
- 商人商会：势力柜台生命周期、原生交易确认和势力状态过滤；
- Mod sidecar：跨重启保存归属、事件窗口、战争与毁灭状态。

## 9.1 本轮纯开发进展

已完成并通过离线自动验证：

- 新增 `unique_pal_campaign.lua`，实现持久化的 `closed -> scheduled -> announced -> activation-pending -> open -> owned` 状态机；
- 开放时间表、预告、原生 Boss 生成回执、捕获回执、超时确定性分配均使用独立 authority 和稳定 operation ID；
- 只有收到精确原生 Actor 生成回执后才进入 `open`，生成失败不会超时白送给 NPC 势力；
- NPC 毁灭战争按玩家是否加入目标势力，确定性路由为后台文本战争或玩家保卫战；
- 后台/玩家战争结果、势力毁灭、城市毁灭、未来刷新抑制策略、商会柜台抑制策略均已形成可持久化 API；
- 商会赎回要求目标势力成员资格、原生金币确认、准确币种与准确配置金额，成功后转移唯一归属并取消待结算战争；
- 新增 `contracts/unique_pal_campaign.v1.json`，并接入 `ContentRuntime`、运行时公共 API、companion 状态和最小作者 SDK；

2. 开放时间表的游戏内通知 presenter 与原生 Boss 生成回执 provider；
3. NPC 后台毁灭战争的游戏内文本 presenter 和逻辑时钟驱动器；
4. 玩家所属势力保卫描述符到现有原生袭击的接线；
5. 势力级毁灭效果 provider，包括刷新抑制、已加载 Actor 清理、空城和商会柜台过滤；
6. 商会唯一性帕鲁赎回 UI、原生金币扣除回执与 Pal 交付；
7. 六只唯一性帕鲁的内容包定义、Boss 槽位和数值配置。

- 势力毁灭后任务、身份、传送点和残余中立 NPC 的处理。
