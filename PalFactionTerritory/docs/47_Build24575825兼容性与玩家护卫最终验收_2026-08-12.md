## 1. 本轮只处理什么

本轮只关闭玩家人类护卫的最后一个缺口：战斗期间让出跟随控制、战斗结束恢复跟随、死亡后释放运行记录和槽位，并允许再次部署。已经验收过的商人商会、四帕鲁攻城、有限信物、原生论道、F5 面板和 FTPoint90 落位没有重跑。

Build `24575825` 的脚本常量、Steam manifest、部署证据和安装审计已同步迁移；Build `24467282` 的文档继续作为对应版本的历史实机证据，不被冒充为新 Build 的重新验收。

## 2. 修复内容

### 2.1 护卫战斗目标过滤

- 原生仇恨系统返回真实敌对目标时，护卫暂停 `MoveToActor` 跟随脉冲，让本体 Visitor Guardman AI 接管战斗。
- 玩家本人和 `IsPlayersOtomo()` 为真的玩家所属帕鲁不会被当作护卫敌人。
- 已死亡目标即使仍短暂残留在本体仇恨系统中，也不会使护卫永久停在战斗状态。

### 2.2 权威死亡观察与运行记录释放

`PalCharacter.OnDeadCharacter` 继续是死亡权威来源。`settlement_raid.lua` 将该事件同时交给攻城结算桥和 `NativeCharacterAdapter:observe_character_death`。适配器确认护卫死亡后会：

1. 标记倒地并停止后续跟随调度；
2. 从原生运行记录中移除该护卫；
3. 通知 `FactionGuard` 释放该势力的单护卫槽位；
4. 通知 QA 实机入口清除旧 handle；
5. 允许同一势力生成新实例。

### 2.3 聚落战斗互为仇恨

攻城袭击者已对聚落居民建立高仇恨。本轮为猎人、警察和 Guardman 类战斗居民增加反向原生仇恨与战斗激活；普通居民和商人不被强制武装。这保证玩家护卫不是单方面等待攻击者接近，而能由本体 AI 接管交战。

## 3. 实机验收

### 3.1 战斗和战后恢复

在 Build `24575825` 的小型聚落实机轮次中，玩家护卫面对原生袭击目标时保留本体战斗控制；敌对目标消失后重新进入跟随路径。该轮同时确认玩家和玩家所属帕鲁不会被护卫当作敌人。

### 3.2 死亡回收与再次部署

自然战斗耗时与伤害随机性较高，因此最终死亡分支使用 UE4SS Lua 调试器调用适配器的正式死亡观察入口；它与正式 `PalCharacter.OnDeadCharacter` 钩子进入的是同一条代码路径。该操作是生命周期语义验收，不宣称拍到了自然战死动画。

关键结果：

```text
CHARACTER_DEATH_OBSERVED ... authority=PalCharacter.OnDeadCharacter
PLAYER_GUARD_DOWNED ... reason=authoritative-death-observed
PLAYER_GUARD_LIVE_TEST_TERMINATED ... runtime=...:qa-0001 ... slotReleased=true saveWrites=0
PLAYER_GUARD_RUNTIME_RELEASED ... runtime=...:qa-0001 ... callback=true detail=notified
```

随后再次按 `Ctrl+F4`：

```text
PLAYER_GUARD_LIVE_TEST_DEPLOYED ... request=qa-0002 actor=...BP_NPC_Hunter_C_2147410673 ... saveWrites=0
```

第一次实例为 `...BP_NPC_Hunter_C_2147411784`，第二次实例为 `...BP_NPC_Hunter_C_2147410673`。请求号和 actor 均发生变化，证明旧运行记录与槽位已释放，不是重复引用旧尸体或旧 handle。
