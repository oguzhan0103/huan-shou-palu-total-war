# 唯一帕鲁商会赎金原生购买桥纯开发验收

日期：2026-08-22

结论：**P2 赎金的代码路线已从“等待直接金币扣除接口”改为复用已经实机证明可工作的原生 ItemShop 服务器购买与结果回执。桥接源码、运行时接线、合同门禁和自动测试完成；2026-08-22 又补齐并实机通过 Build 24575825 的单只 Pal 原生交付路线。正式赎金商品行和 P2 生产 target binding 仍为 0，支付→交付尚未组合验收，因此还不是玩家可用的完整赎回功能。**

## 1. 为什么改用原生商店购买

历史 ObjectDump 可看到玩家物品容器、金币物品和若干库存操作候选，但该 Dump 的 SHA-256 对应 Build 24370881，不能证明 Build 24575825 的直接扣款签名。直接改客户端金币也没有服务器权威和失败回执。

本项目的商人商会已经实机通过 `PalNetworkShopComponent:RequestBuyProduct_ToServer` 与 `RecieveBuyResult_ToClient`。赎金本来就发生在商人商会，因此复用这条原生服务器交易链，既符合设计，也避免新造一条不可靠的货币修改接口。

## 2. 本轮实现

- 新增 `_G.PWFT_UNIQUE_PAL_RANSOM_SHOP_BRIDGE_V1`，并把同一实例交给受信内容模块。
- P2 Provider 可将 Core 生成的 `ransom-offer` 绑定到一个确切原生商品；商品必须库存为 1、购买数量为 1、服务器权威定价、服务器权威返回购买结果。
- 绑定与结算同时核对 `offerId / providerId / bindingId / worldGeneration / shopId / productId / merchantFactionId / currency / amount / buyQuantity / nativeOfferId / ransomPaymentKey`。
- 商店购买成功前不转移唯一帕鲁逻辑归属；失败、错误商品、错误势力、错误价格、错误数量、旧 world generation 和冲突 transaction ID 均失败关闭。
- 赎金购买被 CommerceBridge 标为专用结算，`requestedAward = 0`，不会增加商业好感，也不占用普通商业增长语义。
- 世界卸载时清空临时 offer、商店/商品映射和交易回执，不把 UObject 或运行时 GUID 写入 sidecar。
- 仍由 P2 总线在支付确认后单独发出 `pal-delivery`；本桥明确 `palDeliveryIncluded = false`，不会把“付了钱”伪报成“Pal 已进入玩家容器”。

## 3. 自动测试

专项测试覆盖：

- Core 报价与原生商品价格完全一致；
- 同一 offer 幂等注册、不同签名冲突拒绝；
- 精确商店/商品/势力/价格/数量/generation 匹配；
- 原生购买失败不结算；
- 原生购买成功提交 P2 权威支付回调；
- 支付已成功但状态回调临时失败时，同一笔原生交易可重放，不要求再次购买；
- 同 transaction 同签名幂等，普通商会商品仍走原商业好感；
- 赎金商品始终为 0 商业好感；
- 世界卸载清空临时绑定；
- 运行时烟测确认桥接实例、内容模块上下文、CommerceBridge 事件路由和失败关闭状态均可启动。
