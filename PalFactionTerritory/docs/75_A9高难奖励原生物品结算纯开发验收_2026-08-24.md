## 事务模型

```text
受信结果
  -> RewardPolicy.settle
  -> 持久化原始 rewardIntents
  -> RewardDeliveryBus 写入 pending delivery
  -> 写前侧车持久化栅栏
  -> 精确 OwnerPlayerUId 库存预检
  -> 主机 AddItem_ServerInternal / 客户端 RequestAddItem_ToServer
  -> CountItemNum 精确读回 before + units
  -> applied 并再次持久化
```

关键安全规则：

1. 重复 `operationId` 不重新计算或再发一份；交付层从 `operation_status()` 读取原始持久结果。
2. 交付 ID 固定为 `operationId:channelId`，多频道可以分别完成和恢复。
3. 原生调用前必须保存 `dispatching`、玩家 UID、物品 ID、基线数量、期望数量、Build 和 world generation。
4. 只有同一玩家、同一物品、同一尝试、同一 Build／代际且 `after == before + units` 才标记完成。
5. 原生调用已经开始但结果不明确、数量超出预期、地图卸载或进程在 dispatch 后中断时进入 `reconciliation-required`；不会自动再次发放。
6. 侧车不可写、身份未解析、频道未绑定或 Provider 不可用时保持 `pending`，不碰游戏库存。
7. 不支持金币频道、模型发奖或直接修改 SaveGames payload。

这是一条“歧义时宁可等待人工／后续核对，也不重复发奖”的 at-most-once 路线。Palworld 的本体物品接口没有业务 `operationId` 参数，所以跨崩溃场景不能诚实宣称分布式 exactly-once；当前实现明确暴露该边界。

```lua
local registered = context.rewardDeliveryBus:register_channel({
    schemaVersion = "pwft.reward-delivery-channel.v1",
    channelId = "fan.example.reward.channel.boss",
    providerId = "pwft.native.reward-item.production",
    rewardKind = "item",
    nativeItemId = "StainlessSteel",
    maximumUnitsPerDelivery = 2,

```

```lua
local outcome = context.rewardDeliveryBus:settle({
    schemaVersion = "pwft.reward-settlement.v1",
    authority = "pwft.authoritative-reward-outcome.v1",
    operationId = "fan.example.boss.result.0001",
    contentPackId = "fan.example.pack",
    policyId = "fan.example.reward.boss",
    sourceKind = "boss",
    difficultyScore = 90,
    playerParticipated = true,
    playerSideWon = true,
})
```

示例 SDK 已把 `example.minimal.reward.channel.quest` 演示绑定为 `StainlessSteel`，仅用于说明技术接线；基座正式配置不注册任何奖励频道，也不会自行发物品。
