## 1. 本轮完成范围

- 新增 `contracts/unique_pal_world_effects.v1.json` 和 `unique_pal_world_effect_bus.lua`。
- Provider 由受信内容模块在同一 Lua 环境注册，必须保证 delivery ID 幂等和 world generation 回调隔离；模型、剧情文本和任意客户端字符串没有胜负、支付、清理或交付权。
- 每个毁灭目标必须显式绑定当前 Build 的目标、势力刷新器、允许类、允许清理的 Actor binding/class、城市锚点、居民/功能 NPC 刷新器、商会柜台和原生服务路线。handler 与 binding 不写入 sidecar，世界卸载或恢复后必须重新发现。
- 势力毁灭后输出四类持久世界效果：刷新抑制、精确 Actor 清理、空城、商会柜台过滤；每次新 world generation 重新投递。
- 空城只停止居民和功能 NPC 刷新，明确 `preserveBuildings = true`、`deleteMapActors = false`。
- 清理载荷只包含内容模块预先绑定的 Actor ID 与 Class；`broadActorScanAllowed = false`，不得遍历并销毁无关对象。
- 后台战争输出文本通知并只接受配置化受信 resolver 的权威结果；不要求伪造视野外军队，也不允许模型临场决定胜负。
- 玩家所属势力路线输出原生保卫请求，并把 Provider 返回的 native raid ID 与权威胜负回调一一对应；参与和玩家方胜负必须显式给出。
- 赎回 UI 只能展示 Core 当前 `ransom_quote` 的确切持有者、币种和金额。原生 offer ID、支付 route、`paid=true` 回执全部一致后，Core 才转移逻辑归属并取消待结算战争。
- 支付后的 Pal 原生交付是独立可重试 delivery；Provider 接受请求后进入 `awaiting-confirmation`，只有匹配当前 generation、delivery ID、native delivery ID、玩家、唯一帕鲁和原生路线的权威回调才能完成。交付失败或延迟不重复扣款、不重复转移，也不会伪报已交付。商业好感奖励继续为 0。
- 2026-08-22 新增 `unique_pal_ransom_shop_bridge.lua`：Provider 把 Core 的 `ransom-offer` 绑定到库存为 1 的原生商店商品；只有商店、商品、持有势力、Gold 金额、购买数量、原生 offer、支付 route 和 world generation 全部一致，且 `RecieveBuyResult_ToClient` 报告成功，才向本总线提交支付回调。该购买不会调用普通商业好感结算，也不直接改金币。

## 2. 安全与持久化语义

- 势力毁灭、战争、报价、付款结果和唯一帕鲁逻辑归属仍保存在 Mod 自有 progression sidecar；不修改 Palworld 存档。
- Provider 定义、投递账本、回调签名、赎回 offer 和 world generation 可序列化；UObject、handler 与世界绑定不可序列化。
- 同 callback ID 同签名只重放；同 ID 改变金额、结果、路线或参与状态会冲突拒绝。
- 旧 generation 回调拒绝；返回标题、切图或延迟 sidecar 恢复后，旧 Actor 和 native request 不能继续结算。
- 已毁灭目标的刷新、空城和商会过滤在重新绑定后重放；一次性战争通知、已完成付款和已确认 Pal 交付不重复展示或执行。
