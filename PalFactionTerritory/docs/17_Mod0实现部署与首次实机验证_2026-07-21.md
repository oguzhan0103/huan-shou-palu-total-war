更新时间：2026-07-21。

## 结论

Mod 0 已作为 UE4SS Lua 只读开发切片实现并部署到 Steam build `24181527`。它会加载冻结的第一版势力合同，注册只读地图／传送探针，并在地图加载后扫描本体瞭望塔对象。当前不会绘制势力颜色、不会阻止传送、不会写存档，也不会复用犯罪提示 UI。

这条路线不依赖 UE、Wwise 或 PMK 编译，因此可以先验证真实运行时 ID，再决定本体 UI 资产层的最小修改方案。

## 首次实机验证步骤

1. 正常从 Steam 启动 Palworld；首次 UE4SS 扫描可能比平时慢。
2. 进入一个复制存档或不重要的测试存档。
3. 观察 UE4SS GUI，确认出现 `PalFactionTerritory0` 的 `READY` 行。
4. 打开主世界地图，停留至少 10 秒，让只读塔绑定扫描完成。
5. 使用一次普通公共传送点；Mod 0 只记录调用，不会拦截。
6. 正常退出游戏，不保存任何由本 Mod 写入的数据——当前版本本来就没有写入能力。
7. 回到项目中检查 `UE4SS.log`，把 `READY`、`HOOK_READY`、`MAP_CREATE`、`TOWER_BINDING`、`FAST_TRAVEL_AUDIT` 和任何 `ERROR` 行归档。

## 通过标准

- 游戏能进入主菜单和测试存档，无启动崩溃。
- 日志出现 `READY ... mode=read-only`。
- 地图钩子和传送审计至少各触发一次。
- 塔扫描不引发 Lua 异常，并能解析足够的 `FastTravelPointID` 与遮罩资产。
- 游戏原地图、迷雾、传送与存档行为保持原样。

如果 hook 路径失效或对象字段发生变化，只调整探针；不得直接打开地图写入或传送拦截开关。

## 回滚边界

本次安装前不存在 `Win64\dwmapi.dll` 和 `Win64\ue4ss`。因此在游戏完全退出后，把这两个由本次部署新增的路径移出游戏目录即可完整回滚 UE4SS 与 Mod 0；不要删除或移动 `Palworld-Win64-Shipping.exe`、`Pal-Windows.pak` 或玩家存档。具体新增文件清单与哈希以 `evidence/deployments/mod0-dev-build24181527.json` 为准。
