# B6 动态经济与经济战争实机验收

日期：2026-08-23

游戏版本：v1.0.3.101283 / Steam Build 24575825

结论：`PASS`

## 1. 本次关闭的蓝图缺口

B6 原来已有资源账本与战争状态机，但没有把真实资源事件、原生商店行、重启持久化和停战恢复串成同一条游戏内链路。本次补齐：

1. 七势力、八类矿产账本成为动态经济权威输入；
2. 只修改原生 `ProductArray` 中已经审计过的九种商品，其他原生商品不动；
3. 供应档位直接决定售价、库存或采购价／采购额度；
4. 资源事件刷新已经驻场的固定商会，不重新生成商人；
5. 短缺进入贸易请求、威胁与战争；补给恢复后停战并回到稳定；
6. 账本、冲突和 B6 验收状态写入 Mod 自有侧车，重启后恢复，不写 Palworld 原生存档。

## 3. 经济战争与重启闭环

权威状态依次为：

`trade_requested → threat → war → 退出游戏 → 重启 → war → ceasefire → stable`

战争前记录资源量 49、账本 revision 2、供应方 `pwft.faction.pal_genetic_research_unit`。完整重启后，在正确世界目录 `E0D5ECDC46B379829F8F31A729ACFD92` 读回相同资源量、revision 和战争状态，`persistenceConfirmed=true`。补给导入把存量恢复到 150、revision 3，商店恢复基线售价与库存，最后进入 `complete / stepCount=7`。

## 4. 第一次失败与修复

第一次实机发现当前 Build 的原生 `ProductArray` 是 UE4SS `TArray`，旧实现用 `pairs()` 遍历时失败。运行时保持静态商店，不继续写入动态行，属于失败关闭。

修复后的公共数组迭代器：

- 优先 `GetArrayNum()` 与一基索引；
- 支持 UE4SS `ForEach` 与普通 Lua table 作为后备；
- 单行回调异常立即返回失败，不部分声称成功；
- 自动测试使用真实形状的 TArray fake 覆盖当前 Build 契约。

第二次完整重跑通过。原始失败日志留在私有测试输出，公开结构化证据也保留 `attemptCount=2` 和失败原因。
