# 商人商会供需权威与原生柜台运行时接线

日期：2026-08-07  
状态：**源码闭环与离线回归完成；三个原生运行开关继续关闭；未部署、未启动游戏、未实机验收**

## 1. 本轮解决的两个错位

此前已经生成七套 `PFT_Economy_*` 原生商品行，但仍有两个接线错位：

1. 商业出售结算读取 `faction_commerce.v1.json` 中较早的静态
   `requestedItemIds`，没有以七势力资源供需模型为最终权威。
2. 旧 `faction_merchant_runtime.lua` 的固定商人计划读取原版商店行，且雷恩
   路线包含全图鉴帕鲁商人特例，不能代表“七名商人商会员工”的最终方案。

本轮没有修改地图，也没有启用任何 NPC 生成；只补齐运行时代码和自动验证。

## 2. 现在的权威边界

- 势力出售什么、收购什么：由 `faction_economy.v1.json` 的 commodity signal
  决定。
- 七名商会柜台的普通商人变体、颜色和 `PFT_Economy_*` 行：由
  `faction_economy_shops.v1.json` 决定。
- 原生成功事件、交易防重复和好感度换算：由 `faction_commerce.lua` 决定。
- 每窗口商业好感度封顶、负好感修复和外交敌对来源修复：仍由
  `faction_progression.lua` 决定。
- `faction_commerce.v1.json` 内旧 `requestedItemIds` 只保留为兼容回退，不再是
  基座运行时的最终需求清单。

因此，以雷恩为例，经济模型标记 `IronIngot` 为短缺采购品时，确认出售后可以
进入商业好感度计算；仅存在于旧静态表的 `PalSphere_Master` 不再被误算为该势力
当前短缺品。

## 3. 新增运行时

新增：

`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_economy_merchant_runtime.lua`

公共 API：

`_G.PWFT_ECONOMY_MERCHANT_RUNTIME_V1`

它提供：

- 七名普通 `ItemShop` 商会柜台的确定性站位计划；
- `v04-v10` 普通商人到七个势力商品目录的一一绑定；
- `PFT_Economy_*` 抽选行接入 `NativeCharacterAdapter` 的计划；
- 商人是商会员工、只代表结算对象，不成为对应势力成员；
- 雷恩全图鉴帕鲁商人明确排除；
- 固定市场商业休战元数据，用于敌对关系的有限商业修复；
- 已有地图 Actor 的无所有权绑定；
- 运行时生成、登记、回收和失败时逆序回滚，避免留下半套商人；
- 不写 Palworld 存档。

旧 `faction_merchant_runtime.lua` 暂时保留给来访商队和历史兼容路径，不再作为
七个商人商会经济柜台的权威实现。

## 4. 默认关闭门

实际生成必须同时满足：

```text
config.factionCommerce.nativeEconomyMerchantSpawnEnabled = true
economyShops.runtimeActivation.customProductRowsEnabled = true
economyShops.runtimeActivation.nativeMerchantSpawnEnabled = true
economyShops.runtimeActivation.nativeShopBindingEnabled = true
```

当前四项均未满足，状态为：

```text
nativeEconomyMerchantSpawnEnabled = false
customProductRowsEnabled = false
nativeMerchantSpawnEnabled = false
nativeShopBindingEnabled = false
```

采购补钱和出售好感度开关也继续为 `false`。所以本轮只证明代码可以形成闭环，
不宣称游戏中已经出现商人、商品或好感度变化。
