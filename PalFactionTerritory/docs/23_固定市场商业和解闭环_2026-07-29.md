# 固定市场商业和解闭环

记录日期：2026-07-29  
状态：**源码、合同、UI 数据模型与离线回归已完成；未启动游戏，待集中实机验收**

## 1. 目标

玩家加入某个人类势力后，关系矩阵可能让另一个尚未加入的势力进入外交敌对。该敌对关系不降低数值好感度，但会阻止玩家直接加入目标势力。

本闭环允许玩家在目标势力的固定市场继续交易，分阶段修复一个明确的外交敌对来源。商业只承担辅助修复作用，不替代任务和保卫战。

## 2. 固定规则

- 每个外交敌对来源需要累计 `60` 点商业修复进度。
- 每个外部商业窗口最多计入 `20` 点。
- 只累计已经实际应用的、非负区间商业好感度。
- 目标势力的数值好感度必须不低于 `0`。
- 交易地点必须是带 `commercialTruce = true` 的 `fixed-market`。
- 敌对期间不开放来访商队；来访商队交易不会累计外交修复。
- 多个敌对来源按稳定势力 ID 排序，一次只修复一个。
- 达到 `60` 点后只清除当前敌对来源；溢出点数不转移给下一个来源。
- 成功交易事件 ID 始终被消费；即使本窗口已封顶，重复提交也不能在新窗口再次结算。
- 原有显式修复 API 保留，供后续任务和保卫战使用。

上述数值是 `2026-07-29` 离线平衡基线，集中实机测试后可以调整。

## 3. 数据与接口

- 合同：`contracts/faction_progression.v1.json`
- 进度核心：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_progression.lua`
- 公共 API：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_api.lua`
- 商业结算：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_commerce.lua`
- 原生交易桥：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/commerce_bridge.lua`
- 商人场景元数据：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_merchant_runtime.lua`
- UI 数据模型：`mod0/ue4ss/PalFactionTerritory0/Scripts/pwft/faction_ui_model.lua`

每个势力的快照新增：

- `diplomacyRecoveryAwarded`
- `diplomacyRecoveryProgressBySource`
- `diplomacyRecoveryCompletedCount`

旧快照没有这些字段时会使用安全默认值恢复。

## 4. UI 可读取状态

每个势力行的 `commerce.diplomacyRecovery` 会提供：

- 当前修复来源。
- 当前进度、所需进度和剩余进度。
- 当前窗口已使用与剩余额度。
- 未解决来源列表。
- 各来源历史进度和已完成数量。
- 当前是否满足数值好感度、固定市场和敌对来源条件。

当前只完成 UI 数据模型，玩家可见 UMG 仍是后续开发项。

## 5. 离线验证

定向测试覆盖：

- 固定市场成功交易累计修复。
- 来访商队不累计修复。
- 每窗口 `20` 点封顶。
- 三个窗口累计 `60` 点并自动清除一个来源。
- 多来源顺序和不跨来源转移余数。
- 重复交易事件防护。
- 快照保存、恢复和修复历史保留。
- 商业桥正确传递场景类型与停战资格。
- UI 模型同步显示进度和余额。

`scripts/verify-mod0.ps1` 于 2026-07-29 完整通过。验证未启动 Steam、Palworld 或 UE4SS，也未修改游戏存档和原始 PAK。

## 6. 待实机验收

- 原生购买成功回调是否只结算一次。
- 原生出售服务器成功信号接入后是否只结算一次。
- 敌对玩家是否仍可在固定市场正常交易。
- 达到 `20/40/60` 时 UI、地图、传送和商人状态是否同步刷新。
- 清除一个来源后，其他来源是否仍保持敌对。
- `60` 与 `20` 的节奏是否符合任务/保卫战为主、商业为辅的设计目标。
