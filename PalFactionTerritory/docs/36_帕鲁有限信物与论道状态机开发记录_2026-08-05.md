## 2. 公共接口

内容包注册：

```lua
local api = _G.PWFT_PAL_RECONCILIATION_API_V1

api:register_content("pwft.faction.desert_pal_tribe", {
    contentPackId = "fan.story.desert.v1",
    contentVersion = "1.0.0",
    tokenQuota = 3,
    maximumAffinityPerDiscourse = 40,
})
```

主要接口：

| 接口 | 调用方 | 作用 |
|---|---|---|
| `register_content(factionId, content)` | 内容包 | 首次注册信物总数和单次最大好感度 |
| `migrate_content(factionId, content, migrationId)` | 内容包升级器 | 显式迁移配置；新配额不能低于已掉落数 |
| `record_raid_result(factionId, raid)` | 原生袭击适配器 | 按胜负和头领击杀归属幂等结算一枚随机城邦信物 |
| `complete_token_quest(factionId, tokenId, completionId, context)` | 文本任务运行器 | 把信物从待任务推进到可论道 |
| `preview_discourse(factionId, tokenId)` | 对话 UI | 检查门槛并返回不可逆警告和剩余次数 |
| `begin_discourse(factionId, tokenId, sessionId, context)` | 对话运行器 | 提供器就绪且玩家确认后预留一次机会 |
| `resolve_discourse(factionId, sessionId, outcome, affinity, resolutionId)` | 对话运行器 | 原子结算消耗、好感度、红转蓝或技术返还 |
| `status(factionId)` | UI/内容包 | 查询配额、信物、剩余次数、锁死和和解状态 |
| `token_status(factionId, tokenId)` | UI/任务运行器 | 查询单枚虚拟信物状态 |

`record_raid_result` 只接受带唯一 `raidEventId` 的结果；只有 `playerSideWon = true` 与 `playerCreditedLeaderKill = true` 同时成立才可能掉落。城市从全部七城邦中有放回随机抽取，因此重复结果合法，但每次创建新的信物实例。

## 3. 论道机会状态机

```text
quest-pending
  -> complete_token_quest
quest-complete
  -> providerReady + userConfirmed
reserved
  -> completed       => consumed + 确定性好感度
  -> player_abort    => consumed + 0 好感度
  -> technical_failure / 启动恢复 => quest-complete（返还）
```

补充规则：

- 玩家未确认时不预留、不消耗。
- 每个帕鲁势力同一时间只允许一个活动论道会话。
- 技术失败不消耗；重新载入时发现未结束活动会话，自动按技术失败返还。
- 玩家明确确认后主动中止，消耗信物且不给好感度。
- 单次好感度受内容包 `maximumAffinityPerDiscourse` 限制，累计最多到 `0 / Friendly`。
- 已掉落的全部机会都被消耗而仍小于 `0` 时，写入永久锁死；后续提高内容配额也不会自动解锁该世界的失败结果。

## 4. 离线验证证据

执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-mod0.ps1
```

2026-08-05 结果：退出码 `0`。新增专项覆盖：

- 失败袭击与没有头领击杀归属不掉落；
- 相同 `raidEventId` 不能在事后改写或重复领奖；
- 城邦随机允许重复且每次是独立信物；
- 内容作者配额耗尽后停止掉落；
- 全人类领主门槛；
- 提供器未就绪、未确认、技术失败、主动中止四类消耗差异；
- 单次限额、分次增益、红转蓝和结局门槛；
- 次数耗尽永久锁死；
- 快照恢复时返还中断会话；
- 内容配置迁移和配额下限；
- F5 数据与文字格式；
- 完整运行时烟测和全部旧回归。
