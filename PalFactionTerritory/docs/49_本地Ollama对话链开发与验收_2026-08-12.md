# 本地 Ollama 对话链开发与验收（2026-08-12）

## 结论

本地大模型部分已从“存在独立组件”收敛为一条可执行链路：

`玩家操作台输入 -> Mod 自有命令文件 -> 当前帕鲁代表会话 -> Mod 内 Agent 文件桥 -> 本地 Ollama -> 严格回复白名单 -> 既有游戏内对话面板 -> 玩家 F3 确认建议选择`

源码、真实本机模型、文件桥、操作台和安装部署均已验证。基座仍不携带剧情，也不会凭空创建代表 NPC；最终画面验收需要作者启用内容包并绑定其代表 Actor。

## 本轮补齐内容

- 把 Agent 桥直接实例化在 `PalFactionTerritory0` 的 Lua 环境内，消除不同 UE4SS Mod 全局变量相互不可见的问题。
- 新增 Mod 自有文件桥：严格校验请求和回复、限制大小、拒绝未知字段/重复数组项/未授权选择与结果标签、请求过期后失败关闭。
- 新增操作器：只接受当前活动论道会话，自行取得世界和玩家身份键，500 ms 自动轮询；世界卸载时立即停止读取旧会话。
- 请求 ID 加入运行实例标识，避免重启后把历史 outbox 误认为新回复。
- 操作台增加本地 Ollama 区域，并自动启动 `PalAgentDialogue` release 二进制；默认模型为 `gemma4:e4b`，可用 `PAL_AGENT_MODEL` 覆盖。
- HTTP 写入口只监听 `127.0.0.1`，要求同源 Origin 与每次启动随机令牌；无授权请求返回 403。
- 回复只允许 `dialogue`、白名单内 `proposedChoice` 和白名单内 `resultTags`。模型无好感、任务、货币、物品、战斗、势力、世界或 Palworld 存档写入能力。
- 新增与作者 SDK 最小内容包 ID、上下文键和选择 ID 完全配对的 Agent 角色包。

## 已验证证据

### VERIFIED：真实本地模型

使用本机 Ollama `gemma4:e4b` 执行 `provider-check`：

```text
PROVIDER_CHECK_OK provider=ollama model=gemma4:e4b dialogueChars=11 strictJson=true authorityFields=false
```

### VERIFIED：操作台写入口

- `/api/health` 返回服务就绪、`agentTextSubmission=true`、`directStateMutation=false`。
- 无令牌提交返回 HTTP 403。
- 带同源 Origin 和随机令牌的中文文本连续提交两次均返回 `agent-text-command-queued`。
- 最终命令保留完整中文、活动 `presentationId`，且 `directStateMutation=false`。
- 操作台退出后测试用 companion 与 Agent 子进程均已关闭。

### VERIFIED：自动测试和部署

- `PalAgentDialogue`：`cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo test --locked --all-targets`、release build 全部通过；26 项 Rust/Lua/CLI 测试通过。
- Agent 使用 `run-owned` 监视操作台进程；强制结束操作台后，Agent 子进程在 2 秒内自行退出，避免异常关窗遗留后台进程。
- `PalFactionTerritory`：全量公开验证通过，统计为 53 个 Lua 文件、46 个 Lua 测试、289 个跟踪文本文件。
- Mod 已部署到 Steam Build `24575825`；安装审计确认 51 个运行时文件逐项与当前源码 SHA-256 相同。
- 未启动 Palworld，未触碰 Palworld 存档、原始 PAK 或本体游戏内容。

## 使用方法

1. 确保 Ollama 正在本机 `127.0.0.1:11434` 运行，且已安装 `gemma4:e4b`；如需别的模型，启动前设置 `PAL_AGENT_MODEL`。
2. 启动 `PalFactionTerritory/companion/start-companion.cmd`。操作台会自动启动 Agent sidecar。
3. 内容作者把自己的内容包复制到 `PalFactionTerritory0/Scripts/`，加入 `contentModules.modules`，并绑定精确代表 Actor。
4. 玩家在游戏中与代表开始论道后，在操作台输入自由文本；回复会自动刷新到既有对话面板。
5. 模型建议的确定性分支必须由玩家按 `F3` 确认；数字键仍可直接选择作者写好的离线分支，`F4` 为明确退出。

## 未冒充完成的边界

本轮没有启用 SDK 示例剧情包，也没有创建测试 NPC，因此没有宣称“模型回复已经在某个正式剧情 NPC 头顶/面板上实机显示”。这一步需要内容包与场景 Actor，是剧情密钥侧的集成验收。大模型的基座能力、真实模型连通、输入、桥接、轮询、权限边界和安装部署已经完成。
