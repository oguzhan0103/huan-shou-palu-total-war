# A8 领主护卫原生生产接线：纯开发验收

日期：2026-08-24
当前结论：**源码、合同、自动测试与运行时接线 PASS；真实领主 Actor 场景尚未实机验收。**

## 1. 本轮完成内容

A8 原有 `npc_leader_guard_orchestrator.lua` 已经负责内容定义、势力／领主／场景上限、生命周期意图、幂等和侧车恢复，但此前没有执行这些意图的正式原生 Provider。本轮新增 `npc_leader_guard_native_production.lua`，直接复用已经在玩家护卫链路中实机通过的 `NativeCharacterAdapter`，没有另建 AI 或扫描世界 Actor。

生产链现在覆盖：

- 内容作者声明领主稳定 ID、精确 Actor 类、护卫编组和允许场景；
- 真实领主 Actor 出现后按 Actor key 与 class key 精确绑定；
- `deploy-guards` 把编组原型展开为真实原生 NPC，围绕领主确定性落位；
- 原生 `VisitorLeader` 跟随链继续负责移动；进入战斗时把控制交还本体仇恨／战斗控制器，战斗结束后恢复跟随；
- `leader-death`、`actor-unloaded`、`recall` 和换世界执行整组回收；
- 部分成员生成失败时回滚本轮已经生成的 Actor，不留下半支编队；
- 全体护卫死亡后自动提交一次权威 recall，释放编排器的领主／势力／场景名额；
- 被唯一帕鲁或结局标记为毁灭的势力不再生成领主护卫；
- 不持久化 UObject，不直接修改 Palworld 存档。

## 2. 内容作者可用接口

运行时新增：

```text
PWFT_NPC_LEADER_GUARD_NATIVE_PRODUCTION_V1
```

Core 自动从七个人类势力已核验的商会护卫角色表生成七个默认原型，ID 规则为：

```text
<factionId>.default-guard
```

例如雷恩盗猎集团为 `pwft.faction.rayne_syndicate.default-guard`。内容作者可以直接在 `leader_guards.lua` 编组中引用，也可以调用 `register_archetype(...)` 增加经过当前 Build 核验的角色。Core 不内置剧情领主、领主地点、姓名或护卫故事设定。

完整机器合同：`contracts/npc_leader_guard_native_production.v1.json`。

## 3. 安全与失败关闭

- Provider ID 与 authority 必须同时进入白名单；
- 领主 Actor 的原生完整名称必须包含内容包声明的精确类 token；
- 不使用 `FindAllOf` 或半径广扫寻找领主；
- 编组引用未注册原型、领主位置不可读、势力已毁灭或任一原生生成失败时，整次部署失败关闭；
- 原生回收沿用既有 adapter 的单一路径，避免 Despawn 与 `K2_DestroyActor` 双重销毁；
- 世界卸载先回收生产 Provider 的护卫 Actor，再清除编排器的世界期绑定和部署；
- 模型没有绑定、生成、战斗、回收或状态提交权限。

## 4. 自动验证

新增 `npc_leader_guard_native_production_spec.lua`，并扩展运行时冒烟、原生角色适配器、内容作者 SDK 与公开源校验。最终 `scripts/verify-mod0.ps1` PASS：

- 106 个 Lua 文件；
- 82 个 Lua 测试；
- 436 个受跟踪文本文件公开源扫描；
- 精确类不匹配、缺失原型、势力毁灭、部分生成回滚、跟随／战斗阶段、手动召回、全员死亡自动释放、精确解绑和世界卸载均有回归覆盖。

## 5. 尚未冒充完成的部分

本轮没有启动 Palworld。Core 不应自行指定某个剧情 NPC 为正式领主，因此当前生产状态是：Provider 已受信、七个默认护卫原型就绪、领主绑定数为 0、活动编队为 0。

后续内容作者提供或确认一个真实领主 Actor 后，实机至少需要验证：

1. 精确领主绑定；
2. 两名以上护卫同组生成和围绕领主落位；
3. 跟随、自然战斗让权与战后恢复；
4. 单个护卫死亡和全员死亡的槽位释放；
5. 领主死亡、场景卸载和势力毁灭后的整组回收／抑制；
6. 退出世界后无残留 Actor，原生存档未被直接改写。

自动测试通过不等于上述画面级实机通过，也不等于用户已经验收。
