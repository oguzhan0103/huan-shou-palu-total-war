本文是 `57_好感下降身份降级与权限回收纯开发验收_2026-08-16.md` 的后续。57 号文档证明了“负数如何结算以及降级后如何回收权限”；本文证明受信的伤害、任务和战争系统可以通过统一入口提交负向事件。

## 1. 已完成的路由

新增 `_G.PWFT_FACTION_CONSEQUENCE_API_V1`，当前只接受合同预登记的三类 provider：

| Provider | 原因码 | 用途 |
| --- | --- | --- |
| `pwft.consequence.native-actor.v1` | `friendly-fire`、`civilian-harm` | 人类势力成员或平民受到玩家发起的原生伤害 |
| `pwft.consequence.content-action.v1` | `mission-failure`、`contract-breach` | 内容包的任务失败或违约动作 |
| `pwft.consequence.economy-war.v1` | `war-consequence` | 资源战争状态机或后续权威战争适配器 |

五种事件最终都调用 `FactionApi:apply_reputation_delta`，因此自动继承既有的上下界、单次最多 300 点、稳定签名、操作 ID 幂等、身份降级、护卫回收、任务权限重算、UI/NPC/商人刷新和 sidecar 持久化流程。帕鲁势力仍拒绝负向好感。

## 2. 原生伤害安全边界

成员和平民伤害不能凭 Actor 名、距离扫描或模型文本直接结算。provider 必须先登记：

- 精确 Actor 引用；
- 精确原生 class path；
- 目标所属的人类势力；
- 目标角色 `faction-member` 或 `civilian`；
- 当前世界 generation。

提交事件时还必须同时满足：同一 Actor、同一 class path、角色与原因码匹配、`nativeConfirmed=true`、`playerInitiated=true`、当前 generation 一致。返回标题或切换世界会清除所有 Actor 绑定并递增 generation，旧回调失败关闭。

本轮完成的是可供原生伤害适配器调用的权威路由和生命周期接线。具体 Build 24575825 伤害 UFunction、伤害来源参数、本地玩家归属和成员/平民 Actor 目录尚未实机核验，因此没有在缺少证据时盲绑全局伤害 Hook，也不能宣称“玩家打任意 NPC 已在游戏内自动扣好感”。

## 3. 内容包任务失败和违约

`ContentActionRuntime` 新增白名单动作 `apply_faction_consequence`：

```lua
{
    actionId = "fan.quest.failure.rayne",
    kind = "apply_faction_consequence",
    parameters = {
        factionId = "pwft.faction.rayne_syndicate",
        penalty = 20,
        reasonCode = "mission-failure",
    },
    requiresPlayerConfirmation = false,
}
```

该入口只允许 `mission-failure` 与 `contract-breach`，只允许人类势力，仍受合同单次上限约束。内容包只能预登记动作；运行时事件 ID 决定幂等，同 ID 改内容会冲突失败。剧情文本、Ollama 回复和客户端输入不能直接创建结算。

## 4. 持久化和恢复

- 后果事件账本保存在 progression sidecar 的 `factionConsequences` 扩展节点。
- 已处理 event ID 与 operation ID 都保存稳定签名，支持同内容重放和冲突拒绝。
- 路由在恢复回调中重新绑定到新状态表，并清空不能跨世界保存的 UObject 引用。
- `FactionApi` 完成好感变更后，路由再记录自身账本并触发第二次 sidecar 保存，避免出现“好感已保存、后果幂等记录未保存”的断裂窗口。
- 不修改 Palworld 原生世界存档；模型没有派发或状态写入权限。
